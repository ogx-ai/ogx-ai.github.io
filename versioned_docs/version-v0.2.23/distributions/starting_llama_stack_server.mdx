# Starting a ogx Server

You can run a ogx server in one of the following ways:

## As a Library:

This is the simplest way to get started. Using ogx as a library means you do not need to start a server. This is especially useful when you are not running inference locally and relying on an external inference service (eg. fireworks, together, groq, etc.) See [Using ogx as a Library](importing_as_library)


## Container:

Another simple way to start interacting with ogx is to just spin up a container (via Docker or Podman) which is pre-built with all the providers you need. We provide a number of pre-built images so you can start a ogx server instantly. You can also build your own custom container. Which distribution to choose depends on the hardware you have. See [Selection of a Distribution](./list_of_distributions) for more details.

## Kubernetes:

If you have built a container image and want to deploy it in a Kubernetes cluster instead of starting the ogx server locally. See [Kubernetes Deployment Guide](../deploying/kubernetes_deployment) for more details.
